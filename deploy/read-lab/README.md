# Laboratório local de leitura Monday e VR Mais

Issue transversal: [CEP-ORQUESTRADOR #32](https://github.com/luisotvbim-sudo/CEP-ORQUESTRADOR/issues/32). Esta stack é exclusiva do host de testes e da API no commit `073093770d59e3c32c1a534dc1c1e6b3ae29ff1f` (`codex/personal-history-20-days`, PR #27 sobre PR #26). Não corresponde à `main` nem à produção. O contrato HTTP não foi alterado.

## Isolamento e sequência

1. Confirmar checkout limpo no SHA indicado. Executar `./deploy/read-lab/Initialize-Secrets.ps1`. Criar `.local/read-lab/.env` com `MONDAY_TOKEN_FILE` e `VR_MAIS_TOKEN_FILE` apontando para os arquivos locais autorizados. Os valores dos tokens não são copiados; Compose os monta como secrets somente na API. Restringir ACL da pasta privada ao usuário local, SYSTEM e administradores.
2. Obter um dump customizado (`pg_dump -Fc --no-owner --no-acl`) por conexão de **leitura** já verificada à produção. Validar o catálogo com `pg_restore --list` e guardar o dump apenas em `.local/read-lab/production-clone.dump`, fora do Git. Não enviar o dump, dados ou segredos às Issues, PRs ou logs.
3. `docker compose --env-file .local/read-lab/.env -f deploy/read-lab/compose.yaml config -q` e `build api`. Subir somente `postgres`, com volume novo. Executar `./deploy/read-lab/Restore-Clone.ps1`; ele recusa banco não vazio e API ativa. O banco não publica porta no host.
4. Antes do primeiro start da API, executar `Get-Content deploy/read-lab/neutralize.sql -Raw | docker exec -i cep-real-read-lab-postgres-1 psql -X -q -v ON_ERROR_STOP=1 -U cep_read_lab -d cep_read_lab`. O script limpa sessões, convites, resets, outbox, relatórios/notificações, auditoria e PIN/override; desativa agendas automáticas; restringe domínio de cadastro a `lab.invalid`; invalida senhas e troca os identificadores de login dos usuários clonados. `./deploy/read-lab/Set-LocalAccounts.ps1` cria senhas novas em `.local/read-lab/secrets/` e atribui credenciais locais ao único administrador da organização e ao único membro da cópia revisada. O script recusa outra cardinalidade; adaptar de modo explícito antes de usar outro dump.
5. Executar `docker compose --env-file .local/read-lab/.env -f deploy/read-lab/compose.yaml run --rm migrate` e então `up -d --wait api`. Migrations rodam só no clone. A API usa chave JWT e Data Protection locais; os tokens de produção e sessões clonadas não são utilizados. Email outbox e worker de notificações estão desligados; SMTP aponta ao Mailpit. As integrações externas executam apenas as consultas de leitura implementadas nos adaptadores; sincronização escreve somente no banco local.

API: `http://127.0.0.1:18080`; Mailpit: `http://127.0.0.1:18025`. A porta SMTP e o PostgreSQL não são publicados. Para parar preservando o clone: `docker compose --env-file .local/read-lab/.env -f deploy/read-lab/compose.yaml stop`. Para voltar ao estado anterior aos testes, restaurar o dump em um **novo volume de laboratório**, repetir neutralização e credenciais locais, depois iniciar a API. A imagem por si só não reverte migrations ou dados. Nunca reutilizar essa configuração contra a VM ou o banco produtivo.
